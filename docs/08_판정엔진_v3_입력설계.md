## 3. 분류 조건 (판정 규칙)

판정하는 조건은 **거주 + 나이** 두 가지다. 소득·취업·학적·주거는 판정하지 않고 "본인 확인" 목록(`otherConditions`)으로 보여준다.

### 거주

| 유형 | 규칙 | 결과 |
|---|---|---|
| R7 | 조건 없음 | 충족 |
| R1 | 안산 주민등록 있음 | 있으면 충족 / 없으면 **전입신고하면 충족** |
| R2 | 안산 연속 N년 또는 합산 M년 (전입일 + 이전 거주기간) | 채웠으면 충족 / 덜 채웠으면 **YYYY-MM-DD부터 충족** / 주민등록 없으면 미충족("전입 후 N년") |
| R4 | 안산 주민등록 + 경기도 연속 3년 (경기도 전입일, 없으면 안산 전입일부터) | R2와 같은 방식 |
| R6 | 안산 주민등록 **또는** 안산 소재 학교·직장·사업장 중 정책이 인정하는 것 | 하나라도 맞으면 충족 / 없으면 전입신고하면 충족 |
| R8 | 경기도 주민등록 | 안산 또는 경기도면 충족 / 경기도 밖이면 전입신고하면 충족 / 지역 미입력이면 확인 필요 |
| R10 | 안산 **외** 주민등록 | 안산 주민등록 있으면 미충족, 없으면 충족 |

### 나이

- 만 나이로 계산한다. `age.min`/`age.max`가 비어 있으면 제한 없음.
- 지금 상한을 넘었으면 미충족. 하한에 못 미치면 "하한 나이가 되는 날부터 충족".

### 합치는 순서

1. 거주 또는 나이가 미충족 → **미충족**
2. 거주가 확인 필요 → **확인 필요**
3. 거주가 "전입하면 충족" → **전입신고하면 충족**
4. 거주나 나이에 "날짜부터 충족"이 있으면 → 둘 중 늦은 날짜. 그날 나이 상한을 넘으면 **미충족**, 아니면 **그 날짜부터 충족**
5. 나머지 → **충족**

### 결과 상태 (5가지)

| status | 화면 표시 | 의미 |
|---|---|---|
| `eligible` | 충족 | 지금 거주·나이 요건을 모두 채움 |
| `eligible_if_move_in` | 전입신고하면 충족 | 안산 주민등록만 없음 |
| `eligible_from` | YYYY-MM-DD부터 충족 | 거주기간이나 나이가 모자람. 날짜 계산됨 |
| `check` | 확인 필요 | 입력이 부족해서 판정 못 함 |
| `ineligible` | 미충족 | 지금도, 계산 가능한 미래에도 안 됨 |

## 4. 입력받아야 하는 정보

| 필드 (`key`) | 질문 | 필수 | 언제 보이나 | 쓰이는 유형 |
|---|---|---|---|---|
| `birthDate` | 생년월일 | O | 항상 | 나이 (전체) |
| `ansanRegistered` | 지금 주민등록상 주소가 안산시인가요? | O | 항상 | R1·R2·R4·R6·R8·R10 |
| `ansanMoveInDate` | 안산시 전입신고일 | O | 안산 주민등록 = 예 | R2·R4 |
| `ansanPriorYears` | 이번 전입 전 안산 주민등록 기간(합산, 년) | | 안산 주민등록 = 예 | R2 합산 10년 |
| `gyeonggiBeforeAnsan` | 안산 오기 직전에 경기도 다른 시·군에 살았나요? | | 안산 주민등록 = 예 | R4 |
| `gyeonggiSinceDate` | 경기도로 처음 전입한 날 | O(조건부) | 위 질문 = 예 | R4 |
| `currentRegion` | 지금 주민등록 주소 (경기도 / 경기도 밖) | | 안산 주민등록 = 아니요 | R8 |
| `lifeZones` | 안산 소재 학교 / 직장 / 사업장 (복수 선택) | | 안산 주민등록 = 아니요 | R6 |

- 필수는 사실상 **3개**(생년월일, 안산 주민등록 여부, 전입일)다. 나머지는 "더 정확하게 보기" 단계로 접어 둔다.
- 안산 주민등록이 있으면 `currentRegion`·`lifeZones`는 판정에 영향이 없어서 묻지 않는다.
- `ansanPriorYears`·`gyeonggiBeforeAnsan`을 비워 두면 0 / 아니요로 본다. 이때 결과가 실제보다 **불리하게만** 나오고 잘못 충족되지는 않는다(오탈락 방향의 오차).

## 5. 프론트엔드에 넣는 방법

### 5-1. 흐름

```
input_schema.json ──► 입력 화면 렌더링 ──► profile (localStorage 저장)
                                              │
policies_v3.json ──────────────────────► judgeAll(policies, profile, today)
                                              │
                                     groupByStatus(results) ──► 결과 목록 화면 (그룹별)
                                              │
                                     결과 1건 클릭 ──► 상세 화면 (checks, evidence, selfCheck)
```

### 5-2. 데이터 구조 — 정책 1건 (`policies_v3.json`)

```json
{
  "id": "ANS012",
  "name": "청년인턴 사업",
  "category": "교육일자리",
  "residence": { "type": "R1", "label": "안산 주민등록", "region": "안산시", "basis": "공고일" },
  "age": { "min": 18, "max": 34 },
  "benefit": "시 소속부서 행정사무 보조 4개월 (생활임금 시급 11,710원)",
  "apply": { "start": "2026-07-08", "end": "2026-07-16",
             "periodText": "연 2회(1월·7월 모집). 다음 모집 예상: 2027년 1월",
             "url": "https://apply.jobaba.net" },
  "otherConditions": ["미취업"],
  "bonus": { "text": "안산 거주 3년 이상 / 5년 이상 가점", "years": [3, 5] },
  "evidence": "공고일 기준 안산시 주민등록이 되어 있는 18세 이상 34세 이하 미취업 청년 (제2026-1431호 공고문)",
  "sourceUrl": "https://www.ansan.go.kr/..."
}
```

`residence`는 유형마다 들어가는 칸이 다르다: R2·R4는 `minContinuousYears`·`minCumulativeYears`(R4는 `periodRegion`도), R6은 `altZones`, R10은 `excludeRegion`.

### 5-3. 사용자 입력 (`profile`, localStorage `ansan-benefit-profile`)

```json
{ "birthDate": "2004-03-15", "ansanRegistered": true, "ansanMoveInDate": "2025-02-02",
  "ansanPriorYears": 0, "gyeonggiBeforeAnsan": false, "lifeZones": ["학교"] }
```

### 5-4. 판정 결과 1건 (`judgePolicy` 반환값)

```json
{
  "id": "ANS044", "name": "안산꿈키움(대학) 장학금",
  "status": "eligible_from", "statusLabel": "2028-02-02부터 충족", "eligibleFrom": "2028-02-02",
  "hint": "2028-02-02부터 충족",
  "checks": [
    { "key": "residence", "label": "거주 (R2 안산 거주기간)", "state": "from",
      "text": "연속 3년 또는 합산 10년 필요 → 안산 연속 1.7년" },
    { "key": "age", "label": "나이", "state": "ok", "text": "만 ~29세 → 지금 만 22세" }
  ],
  "selfCheck": ["국내 대학 재학생(직전학기 90점 이상, 휴학생 제외)"],
  "bonus": null,
  "recruit": { "state": "closed", "label": "이번 모집 마감", "note": "예정 일정" },
  "evidence": "공고일 기준 안산시에 3년 이상 주민등록을 두고 거주하거나 …",
  "sourceUrl": "https://www.ansan.go.kr/..."
}
```

### 5-5. 화면과 필드 연결

| 화면 (10/28 UI 초안) | 쓰는 필드 |
|---|---|
| 조건 입력 | `input_schema.json`의 `steps` → `fields` (`showIf`로 조건부 표시) |
| 결과 목록 | `groupByStatus()` 그룹 순서: 충족 → 전입신고하면 충족 → 날짜부터 충족 → 확인 필요 → 미충족. 카드에 `name`, `statusLabel`, `recruit.label`(D-day), `hint` |
| 상세 | `checks`(조건별 판정), `evidence` + `sourceUrl`(근거 인용), `selfCheck`(본인 확인 체크리스트), `bonus`, `apply.url` |
| 미전입 사용자 결과 | `eligible_if_move_in` 그룹 개수 = "전입신고하면 N건 더" |
| D-day / .ics | `recruit.state`가 `open`·`upcoming`인 것만. `apply.start`/`apply.end` |

`recruit.state`: `open`(접수 중, 마감 D-day) · `upcoming`(접수 예정) · `always`(상시) · `closed`(마감, `note`에 다음 모집 예상) · `unknown`(공고 확인).

### 5-6. 사용 예시

```html
<script type="module">
  import { judgeAll, groupByStatus } from './judge.js';
  const { policies } = await (await fetch('./policies_v3.json')).json();
  const profile = JSON.parse(localStorage.getItem('ansan-benefit-profile'));
  const groups = groupByStatus(judgeAll(policies, profile));
  // groups.eligible, groups.eligible_if_move_in, groups.eligible_from, groups.check, groups.ineligible
</script>
```

## 6. 테스트 결과 (기준일 2026-11-01)

| 페르소나 | 충족 | 전입하면 충족 | 날짜부터 충족 | 미충족 |
|---|---|---|---|---|
| 도현 (2004-03-15생, 2025-02-02 안산 전입, ERICA) | 45 | 0 | 6 | 1 |
| 전입신고 안 한 ERICA생 (주소 경기도 밖) | 30 | **15** | 0 | 7 |

- 도현: 장학금 4종·학원비는 **2028-02-02부터 충족**. 청년기본소득은 거주(2028-02-02)와 나이(만 24세, 2028-03-15) 중 늦은 **2028-03-15부터 충족**. 안산에서 살아보기만 미충족(안산 시민이라).
- 미전입 학생: **15건은 전입신고만 하면 바로 충족**. 창업스쿨·참여기구·시민DJ는 주민등록 없이도 ERICA 재학으로 충족.
- 나이 경계 확인(1997-12-10생): 장학금 3종은 거주 요건을 채우는 2028-02-02에 만 30세라서 "그때는 나이 상한 초과"로 미충족 처리됨.
- 지금 모집 중: 응시료 지원(마감 D-33), 착한부동산·청년도전지원(D-60), 청년기본소득 4분기(접수 D-1).

## 7. 한계와 다음

- 기준일(공고일/신청일)은 표시만 하고 판정은 오늘 기준이다. 이미 지난 공고는 "다음 공고 기준 예상"으로 읽어야 한다.
- R4 합산 10년(경기도)은 입력을 받지 않아 연속 3년만 본다(불리한 방향 오차).
- 소득·취업·학적은 판정하지 않는다. 다음 단계에서 선택 입력으로 추가할 후보.
- 신청기간은 2026년 값이다. 새 공고가 나오면 `build_v3.py`에서 고치고 다시 실행.
